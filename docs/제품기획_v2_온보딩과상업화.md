# 제품기획: Access v2 — 온보딩 마법사와 상업화 로드맵 (2026-11-01)

작성: ZCode (사용자 심층 인터뷰 4라운드 + 시장조사 기반) · 상태: 방향 확정
**v1.1**: 사용자 요구사항 9건(자동 감지·토글 설정창·지식상태·요약 시스템) + 랭킹 기반 지원순서 + 인터뷰 라운드 4 반영

## 한 줄 비전

**누구나 자기 에이전트 함대와 Access를 5분 안에 연동하고, 에이전트들의 협업을 바탕화면
포스트잇으로, 파일럿(사용자)이 해야 할 일을 전용 포스트잇+폰 푸시로 받아보는 시스템.**
에이전트는 업무를 마치면 파일럿의 지식 수준에 맞춘 **간결한 요약**을 Access에 기입한다.

## 아키텍처 원칙 (요구사항 9번 — 명문화)

> **Access는 LLM이 아니다.** Access 자체는 어떤 LLM도 호출하지 않는다. 각 에이전트 도구가
> MCP(또는 REST)로 Access에 **쓰기만** 한다. 난이도 조정 같은 "지능"이 필요한 것은 전부
> **도구 설명문·SKILL.md 주입**으로 각 에이전트의 LLM에게 위임한다. 사용자는 오케스트레이션
> 뷰(포스트잇)로 그 결과를 본다.

## 요구사항 → 설계 매핑 (사용자 정의 9건)

| 요구 | 설계 |
|------|------|
| 1. 자동 에이전트 감지 | 마법사 3단계 + 설정창 "다시 스캔" 버튼. 감지=설정 디렉토리 존재 검사 (경로표 참조) |
| 2. 토글식 설정창, 활성만 포스트잇 | 설정창 UI 스펙 섹션. **OFF = 포스트잇 숨김 + MCP 등록을 백업 후 제거** (연동도 끊김) |
| 3. 지식상태 3단계 설정 | 4단계로 확장(자동 포함). 설정 저장 후 즉시 다음 요약부터 적용 |
| 4. 도구 업데이트에도 연동 유지 | 자가 치유 설계 섹션 |
| 5. 업무 완료 시 요약 기입 | 기존 `complete_todo(summary=...)` 확장 — 요약 스타일 가이드가 지식상태를 따름 |
| 6. 난이도별 요약 정의 | 지식상태 설계 섹션의 가이드라인 표 |
| 7. LLM 자율 판단 여부 | **하이브리드로 결정**: '자동' 옵션. 고급=에이전트 Soul 자율, 자동=단계 선택까지 자율 |
| 8. 간결·핵심 요약 | 요약 규격(14번) + 도구 설명문에 "3줄 이내" 강제 가이드 |
| 9. LLM-free, MCP 쓰기 도구 | 아키텍처 원칙으로 명문화. 주입 경로 = 도구 설명문 + SKILL.md |

## 설정창 UI 스펙 (레퍼런스: 사용자 제공 이미지 — 다크모드 토글 카드)

```
┌─ Access 설정 ────────────────────────────────┐
│ 파일럿 지식상태  [초보][중급][고급][자동✓]      │
│ 동기화          [Gist][로컬 전용]              │
│ ┌───────────────────────┐ ┌────────────────┐ │
│ │ ◉ Claude Code         │ │ ◉ Codex        │ │
│ │ 설치됨 · 연결됨         │ │ 설치됨 · 연결됨  │ │
│ │ 연결 관리              │ │ 연결 관리       │ │
│ └───────────────────────┘ └────────────────┘ │
│ ┌───────────────────────┐ ┌────────────────┐ │
│ │ ○ Kilo Code           │ │ ○ Cline        │ │
│ │ 설치됨 · 미연결         │ │ 미설치          │ │
│ └───────────────────────┘ └────────────────┘ │
│                        [다시 스캔] [마법서 재실행]│
└──────────────────────────────────────────────┘
```

- **카드**: 브랜드 아이콘 + 이름 + 상태(설치/버전/연결) + 우상단 토글 + "연결 관리" 액션(재등록·백업 열기)
- **토글 ON** → 해당 에이전트 포스트잇 표시 + (미등록이면) MCP 자동 등록
- **토글 OFF** → 포스트잇 숨김 + MCP 등록을 백업 후 제거
- 진입: 트레이 아이콘 메뉴 + 각 포스트잇 상단 ⚙ 버튼
- 설정 저장: `<exe-dir>/access-settings.json` — `{enabled_agents, pilot_level, sync_mode}`

## 지식상태(요약 난이도) 설계

| 단계 | 파일럿 상정 | 요약 스타일 가이드 (도구 설명문/SKILL.md에 주입) | 예시 |
|------|------------|--------------------------------------------------|------|
| 초보 | 바이브코딩 처음 + 비전공자 | 전문용어 금지, 일상 비유 필수, "무엇을 위해 했는지" 중심 | "코드 사본을 클라우드 저장소에 올려 유실 대비를 마쳤어요" |
| 중급 | 바이브코딩 경험 + 비전공자 | 핵심 키워드 + 가벼운 비유 병행 | "git push로 원격 백업 완료 — 'USB 백업'의 클라우드판" |
| 고급 | 전문가 | **에이전트의 Soul(기본 성격)이 자율 판단** — 기술 용어 그대로, 스타일 제약 없음 | "origin/main으로 push 완료, CI 트리거됨" |
| 자동 | — | "대화 흔적으로 파일럿 수준을 추정하고 그 수준으로 써라. 판단 불가 시 중급" | (에이전트별 상이) |

**주입 메커니즘 (LLM-free 유지)**:
1. MCP 서버가 시작 시 `access-settings.json`을 읽어 **도구 설명문(tools/list)에 현재 지식상태 가이드를 삽입** — 전체 4단계 가이드 + "현재 설정: X"
2. 신규 MCP 도구 `get_pilot_profile` — 에이전트가 요약 작성 직전 호출하면 현재 지식상태+가이드 반환 (설정 변경을 재접속 없이 반영하는 통로)
3. SKILL.md에 "Access 요약 프로토콜"로 문서화 (마켓 배포본과 동일 내용)

**요약 규격 (공통 강제)**: 핵심 결과 1줄 + (초보/중급만) 비유 1줄. 최대 3줄. 파일럿 포스트잇 항목에는 "왜 이 행동이 필요한가" 1줄을 추가.

## 업데이트 내성 — 연결 자가 치유

**문제**: 에이전트 도구 업데이트 시 설정 파일이 초기화되거나 스키마가 바뀌어 MCP 등록이 사라질 수 있음.

**설계**:
1. **건강 검사**: Access 시작 시 + 6시간 주기로 각 활성 에이전트의 설정 파일에 `access-todo` 등록 존재 검사
2. **자동 재등록**: 등록 소실 감지 → 설정 파일 타임스탬프 백업 후 재등록 → 토스트 알림("Claude Code 업데이트로 연결이 풀려 자동 복구함")
3. **스키마 변화 대응**: 감지한 설정 형식이 기대와 다르면(파싱 실패) 자동 수정하지 않고 설정창에 "수정 필요" 배지 + 안내 표시 — 잘못된 수정으로 도구를 망가뜨리지 않게
4. **CI**: 각 도구 설정 형식의 파서 통합 테스트를 repo에 유지, 형식 변경 소식 감지 시 업데이트
5. MCP 프로토콜 자체는 안정적 — 위협 요인은 '설정 파일 스키마'와 '실행 위치 변경'뿐 (등록 커맨드는 항상 설치 위치 절대경로)

1. 오케스트레이터(실행)는 포화, **"상태 공유 + 파일럿 어텐션 + 맞춤 요약"은 공백**
2. 스킬 마켓 시세 $3–10 단발성 (Agensi 몫 70%) — 스킬은 수익원이 아닌 **홍보 채널**

## 로드맵

### P0 — 스킬 패키징 & 무료 리스팅 (며칠)

- `skills/access-todo/` SKILL.md: Access MCP 도구 사용법 + **요약 프로토콜(지식상태 4단계·3줄 규격)** + 파일럿 지정 태그(`agent:user`)
- README 영문 병기 + 로드맵 섹션
- Agensi 무료 등록 + SkillHQ 병행
- **완료 기준**: SKILL.md가 Claude Code에서 발견·실행됨, Agensi 라이브 링크 확보

### P1 — 온보딩 마법사 + 설정창 + 자동 연동 + 자가 치유 (수 주)

마법사 5단계: ① 모드 선택(Gist/로컬 전용) ② PAT 발급 안내(클라우드 모드)·Gist bootstrap
③ **에이전트 자동 감지 → 선택** ④ **자동 등록**(경로표, 백업 후 수정, 재시작 안내) ⑤ 완료·포스트잇

- **설정창**(다크모드 토글 카드): 활성/비활성, 지식상태 4단계, 재스캔, 연결 관리
- **자가 치유**(건강 검사+자동 재등록+알림), **지식상태 주입**(도구 설명문+`get_pilot_profile`)
- 지원 순서: 즉시(ZCode·Hermes) → 1차(Claude Code·Kilo Code·pi·Codex·Cline)
- 배포: GitHub Releases + 인스톨러, `cargo build --release --features custom-protocol`
- **완료 기준**: 비개발자가 토큰 없이(로컬 모드) 설치→마법사→1차 도구 자동 등록→토글 ON→포스트잇+요약 표시까지 도달. 의도적으로 등록 삭제 후 Access 재시작 시 자동 복구됨.

### P2 — 파일럿 포스트잇 + 요약 표시 + 폰 푸시

- 파일럿 전용 포스트잇: `agent:user` 태그 TODO 집계, '승인 대기/결정 필요/확인 요망' 구분, **항목별 배경 요약 1줄**
- MCP 도구 `request_pilot(title, kind)`
- **요약 표시**: 각 에이전트 포스트잇 하단 최신 요약 1–2줄 (지식상태 반영)
